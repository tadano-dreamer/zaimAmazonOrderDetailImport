## 決定サマリ(2026-07-18 確定)

| 論点 | 決定 |
|---|---|
| 配布 | **GitHub Pages**(無料・URL公開) |
| 計上日の既定 | **JST(発送日ベース)**。UTC 切替は UI に残す |
| 返金の扱い | **ネット集約**(返金を注文から差引き1行) |
| カード選択 UI | **プルダウン**(ZIP から自動検出・件数付き) |
| 各セレクタの選択肢数 | **2〜3個を目安**。具体の選択肢は**実装が進んでから確定**(UI は最小に保つ) |

### 追加決定(2026-09-06 ― Zaim 実績との突合を受けて)

| 論点 | 決定 | 理由 |
|---|---|---|
| カード選択 UI | **チェックボックスで複数選択**(利用期間付き)。プルダウンから変更 | カード更新で下4桁が変わり、単一選択だと切替以降が丸ごと落ちた(実データで 41,139円) |
| カード切替の検出 | 選択カードの利用停止後に始まったカードを**後継候補として警告＋ワンタップ追加** | 切替に気付けないと静かに欠落するため |
| 出力範囲 | **期間フィルタを追加。開始日・終了日の2値が真実の源で、月プルダウンはそれを埋めるショートカット** | Zaim へは月ごとに取り込む運用だが、取り込み済みの翌日から、といった**1日単位**の切り出しも要る |
| 画面に出す設定 | **カードと期間だけを常時表示**。計上日(発送日/注文日・JST/UTC)・まとめ方・固定値は「詳細設定」に畳む | ユーザーが自分で選ぶことはない設定。既定のまま使うので前面に出す価値がない(消さずに畳むのは、UTC 切替などを残すため) |
| ギフト券併用 | **実請求額の手動入力で上書き可能に**(警告だけでは足りない) | 充当額が注文履歴に無く、データからは復元不可能。総額のままだと Zaim とズレる |
| 複数出荷の分割計上 | **注記のみ**(合計は一致するので勘定はズレない) | カード側は出荷ごとに請求が立つため 1対1 で突合できない |

## 1. 目的・スコープ

スマホ(Web)で Amazon の注文履歴 ZIP を投入すると、Zaim インポート用 CSV を
その場で生成・ダウンロードできる**簡単な Web アプリ**を作る。

- **入力**: Amazon から書き出した `Your Orders.zip`(そのまま投入)
- **出力**: Zaim 取込用 CSV(`日付,カテゴリ,カテゴリの内訳,お店,支払い元,品目,支出金額`)
- **選択可能**: 抽出カード下4桁 / 計上日の基準(発送日・注文日, JST・UTC) / 固定値(カテゴリ・内訳・お店・支払い元) / 合算 ON・OFF / 返金の扱い
- **非目標(今回やらない)**: Zaim への自動連携(API 投入)、複数アカウント管理、サーバ保存、ログイン

---

## 2. 設計の要 ― アーキテクチャ判断(最重要)

### 採用: **クライアントサイド完結の静的 Web アプリ**(ブラウザ内で全処理)

ZIP の解凍・抽出・CSV 生成をすべて**ブラウザの JavaScript で実行**し、サーバを持たない。

| 観点 | クライアント完結(採用) | サーバ処理(不採用) |
|---|---|---|
| コスト | **¥0**(静的ホスティング無料枠) | サーバ/関数の費用・制限 |
| プライバシー | **データが端末外に出ない** | 請求先住所・氏名がサーバへ送信される |
| シンプルさ | 静的ファイルのみ・ビルド不要 | バックエンド・デプロイ・CORS 対応 |
| スマホ対応 | ブラウザだけで完結 | 同左だが構成が重い |

> **プライバシーが決定打**: `Order History.csv` には `Billing Address`(氏名・住所)が含まれる。
> クライアント完結ならこの個人情報を一切ネットワークに流さずに済む。コスト・シンプルさの
> 要件とも完全に一致するため、サーバ案は採らない。

## 3. 技術スタック(コスト0・ビルドなし)

- **HTML + バニラ JS**(フレームワーク・ビルドツールなし。`index.html` 中心の最小構成)
- **JSZip**: ZIP をブラウザ内で解凍(必要な2ファイルだけ取り出す)
- **CSV パース**: PapaParse(引用符付きフィールドを安全に処理)or 自前の小型パーサ
- **出力**: `Blob` + `URL.createObjectURL` でダウンロード。UTF-8 BOM 付きで生成
- **依存の入れ方**: CDN 参照でも良いが、**ライブラリはローカルに同梱**(`/vendor/`)して
  オフライン動作・CDN 障害非依存にする(数十 KB。コストゼロ)

## 4. 画面・入力仕様

単一画面。上から順に操作するだけ。

1. **ZIP 選択**: `<input type="file" accept=".zip">`(スマホのファイル/写真アプリから選択)
2. **カード選択**: ZIP を読んだら `Payment Method Type` を**自動集計してプルダウン表示**
   - 例: `Visa - 5171 (56件)` / `Visa - 1745 (107件)` … を件数付きで列挙(手入力より事故が少ない)
   - 「5171 を含む」方式なのでギフト券併用(`Gift Certificate/Card and Visa - 5171`)も拾える
   - 複数選択可(将来: 1カードずつ別 CSV 出力も可)
3. **計上日の基準**(既定は実態一致設定)
   - 日付ソース: ● 発送日(Ship Date) / ○ 注文日(Order Date)
   - タイムゾーン: **● JST(既定)** / ○ UTC ← **今治=7/9 か 7/8 かの切替**
4. **合算**: ● 出荷単位で合算(推奨) / ○ 明細1行=1エントリ
5. **返金の扱い**: **● ネット集約(確定)**。※別行表示は今回作らない(将来拡張)
6. **固定値(編集可能・既定値入り)**
   - カテゴリ = `生活費` / 内訳 = `ゆうすけインポート` / お店 = `Amazon` / 支払い元 = `ゆうEPOS`
7. **プレビュー表**: 生成結果を表で表示(件数・合計金額・期間・返金注記も表示)
8. **ダウンロード**: `zaim_import_<card>.csv` を保存(＋「表をコピー」ボタンも用意)

> スマホの保存挙動対策: iOS Safari はダウンロードが不安定なため、
> ①ダウンロード ②共有シート ③プレビューをコピー の3経路を用意する。

## 5. コアロジック(既存 Python からの移植)

`amazon_to_zaim.py` が**確定した参照実装(oracle)**。同じ振る舞いを JS へ移植する。

移植する関数と責務:
- `parseAmount("2,200") → 2200`(カンマ・¥ 除去)
- `parseDate(iso, jst) → "YYYY-MM-DD"`(UTC→JST 変換の有無を選択)
- `loadRefunds(Refund Details.csv) → {OrderID: 返金合計}`
- `combineNames([...]) → "A / B×2"`(同名は ×N、出現順保持)
- `convert(...)`:
  1. カード一致 & 購入成立(Cancelled 除外)の明細を抽出
  2. `(Order ID, 発送日)` で出荷グループ化 → `Total Amount` を合計
  3. 返金を該当注文(最新発送日のグループ)から差引
  4. 日付昇順で Zaim 7列へ整形

ZIP から取り出す対象(他の PDF 群は無視):
- `Your Orders/Your Amazon Orders/Order History.csv`
- `Your Orders/Your Returns & Refunds/Refund Details.csv`(無くても動く)

## 6. 変換ルール(実態=カード明細に合わせる ― 検証済み)

| ルール | 内容 | 検証例 |
|---|---|---|
| 出荷単位で合算 | 同一注文・同一発送日の明細を1件に合計 | 紙コップ477+シルコット1180=**1,657** / 今治2,370×2=**4,740** |
| 発送日(既定 JST)で計上 | Order Date でなく Ship Date、日本時間へ変換 | サンナップ **6/30** / 今治 **7/9(JST)** |
| 返金を差引 | `Refund Details.csv` の返金を注文から減算 | レノア 1,811 − 200(発送遅延)=**1,611** |

`Total Amount` は税込・送料込・割引後の明細金額。合算後合計は 127,096 − 返金200 = **126,896円**。

**要注意ケース(UI で注記表示)**: ギフト券併用注文(例 Matdeco 5,760円)は
カード実請求額より多く出る(内訳分離不能)。手動調整できるよう画面で警告する。

## 11. 確定事項と、実装中に詰める点

### 確定(2026-07-18)
- **配布**: GitHub Pages でURL公開。

  2択に留めるか、合算 ON/OFF を出すか等)。まず動くものを作り、画面を見ながら間引く。
- 固定値プリセットの持たせ方(既定値の初期表示のみか、複数プリセットを選べるようにするか)。
- スマホでの保存経路(ダウンロード/共有/コピー)のうち、実機で確実な方式に寄せる。
